# Сборка и проверка

## Что нужно

- **Python 3.8 или новее.** Скрипт сборки использует только стандартную библиотеку.
- **vasm**, собранный с бэкендом семейства 6800 и модулем синтаксиса Motorola. Исполняемый файл
  называется `vasm6800_mot`. Сайт vasm: <http://sun.hasenbraten.de/vasm/>. В CI используется
  зеркало на GitHub `StarWolf3000/vasm-mirror`, закреплённое на коммите
  `a13e7e728a3dd5a9ba468bf479119e0bc23e70fd`.
- Для перегенерации исходника (необязательно): `pip install capstone` и дампы ПЗУ (см. `roms/README.md`).

## Сборка vasm

### Linux / macOS

```sh
git clone https://github.com/StarWolf3000/vasm-mirror.git vasm
cd vasm
make CPU=6800 SYNTAX=mot
# результат: ./vasm6800_mot
```

### Windows (Visual Studio)

Откройте «x64 Native Tools Command Prompt for VS» (есть в любой редакции Visual Studio с компонентом
C++) и выполните:

```bat
git clone https://github.com/StarWolf3000/vasm-mirror.git vasm
cd vasm
nmake -f Makefile.Win32 CPU=6800 SYNTAX=mot
rem результат: vasm6800_mot.exe
```

## Сборка прошивки

Укажите скрипту, где лежит vasm, одним из трёх способов:

- переменная окружения `VASM` с полным путём к исполняемому файлу;
- копия исполняемого файла в `tools/bin/`;
- исполняемый файл в `PATH`.

Затем:

```sh
python tools/build.py            # все варианты
python tools/build.py 5007033    # один вариант
```

Образы записываются в `build/<вариант>.bin`, листинги в `build/<вариант>.lst`. Скрипт сравнивает
SHA-256 каждого образа с хешем из `annotations/variants.json` и завершается с ошибкой при любом
расхождении.

Когда вы начнёте менять код, проверка хеша, разумеется, перестанет проходить. Для изменённых сборок
используйте `python tools/build.py --no-verify <вариант>`, а неизменённые варианты должны
по-прежнему собираться байт в байт.

## Работа в Visual Studio / VS Code

Откройте папку репозитория через «Open Folder». Исходники — обычные текстовые файлы, а сборка и
перегенерация — консольные скрипты на Python, их можно запускать как внешние инструменты или
задачи. Подсветка синтаксиса «Motorola 68000/6800 assembly» в любом редакторе подходит неплохо.

## Как получается исходник

Файлы в `src/` генерируются и лежат в репозитории, чтобы их можно было читать и собирать без
дополнительных инструментов. Они получаются из двух входов:

1. Дамп ПЗУ каждого варианта (в репозиторий не входит).
2. База аннотаций в `annotations/`:
   - `rom_labels.json`, `ram_symbols.json` — имена кода, данных и ячеек ОЗУ;
   - `tables.json` — описания калибровочных таблиц (имя, тип, оси, описание);
   - `code_seeds.json` — дополнительные точки входа в код, которые статический анализ сам не находит;
   - `pointer_words.json` — слова данных, которые являются указателями и выводятся как метки;
   - `modules.json` — разбивка адресного пространства на файлы исходника;
   - `routines.md` — имена и описания подпрограмм (пишутся вручную);
   - `comments.txt` — комментарии к отдельным командам, по одному на строку: `АДРЕС  текст`.

`tools/gen_source.py` дизассемблирует код рекурсивным обходом: начинает с векторов прерываний и
точек входа и проходит по всем ветвлениям и вызовам. Затем каждый байт выводится либо как команда,
либо как данные, с метками, шапками подпрограмм и автоматическими комментариями: смысл аппаратного
регистра или калибровочной таблицы, краткое описание вызываемой подпрограммы.

Рекомендуемый порядок работы:

```sh
# правим annotations/routines.md (например, описываем подпрограмму)
python tools/gen_source.py --roms roms
python tools/gen_cal_docs.py --roms roms
python tools/gen_fault_docs.py --roms roms
python tools/build.py           # по-прежнему должно быть OK для всех вариантов
```

Пока аннотации развиваются, не правьте `src/` вручную: следующая перегенерация затрёт правку.
Позже, для доработанной версии «Enhanced Edition», исходник будет отделён в свою ветку и
поддерживаться вручную.

## Почему сборка точная

- Каждая команда выводится с явным режимом адресации: `<` задаёт прямую (8-битную), `>` расширенную
  (16-битную) адресацию, так что ассемблер не может выбрать другую кодировку.
- Всё, что не распознано как код, выводится байтами данных. Ошибка в разделении кода и данных может
  ухудшить читаемость, но никогда не меняет результат.
- Метки, указывающие внутрь команды или блока данных, задаются абсолютными константами
  (`src/inc/inner_labels.inc`).
