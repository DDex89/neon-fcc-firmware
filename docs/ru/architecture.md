# Железо и архитектура прошивки

Утверждения с пометкой *(выведено)* получены чтением кода и пока не подтверждены на реальном железе.

## Блок управления

Блок управления Neon 1995 года («FCC», Four Cylinder Controller) имеет один 60-контактный разъём. С
1996 года на Neon стоит SBEC III с двумя 40-контактными разъёмами — это другое железо и другая
прошивка.

Процессор — Motorola **68HC11** в расширенном режиме. Раскладка регистров, которую использует код
(OPTION по $1039, INIT по $103D, BPROT по $1035, окно EEPROM по $B600), соответствует семейству
68HC11 A/E. Программа хранится во внешнем (E)EPROM, который занимает $1200-$FFFF: 60 928 байт, ровно
размер дампов `.bin`.

## Карта памяти

| Диапазон | Содержимое |
|---|---|
| `$0000-$00FF` | ОЗУ прямой страницы: самые используемые переменные (8-битная адресация) |
| `$0100-$03FF` | ОЗУ: остальные переменные, данные кодов ошибок, буферы |
| `$0400-$0437` | Регистры внешнего устройства ввода-вывода (в исходном дизассемблере «PIA»). Заполняются из таблицы после ResetInterrupt. Оно же управляет **форсунками**: длительности по цилиндрам в `$0424/$0428/$042C/$0430`, регистр команды `$0410`, состояние в `$0400/$0401`. Бит 4 регистра `$0409` переключается на каждом проходе главного цикла («пульс»). *(выведено)* |
| `$0438-$04FF` | ОЗУ и стек (указатель стека стартует с $04FF) *(выведено)* |
| `$1000-$103F` | Внутренние регистры 68HC11 (`src/inc/hc11_regs.inc`) |
| `$1200-$B4CC` | Код программы, часть 1 |
| `$B4CD-$B5FF` | Не используется ($FF) |
| `$B600-$B7FF` | Окно внутреннего EEPROM процессора. Здесь процессор видит EEPROM, а не образ EPROM; контрольная сумма ПЗУ этот диапазон пропускает. |
| `$B800-$E228` | Калибровки: заголовок (номер детали, флаги конфигурации) и около 460 таблиц и констант |
| `$E229-$FFD5` | Код программы, часть 2; строка копирайта по адресу $FFA4. $FDDA-$FFA2 (457 байт, включая запасной байт контрольной суммы $FF50) и $FFC0-$FFD5 (22 байта) не используются ($FF) |
| `$FFD6-$FFFF` | Векторы прерываний |

### Заголовок калибровки

| Адрес | Смысл |
|---|---|
| `$B800-$B801` | Байты идентификатора калибровки |
| `$B802-$B805` | Номер детали в BCD, например `05 00 70 33` = 05007033. **$B805 — ещё и эталон контрольной суммы ПЗУ.** |
| `$B806` | Ревизия |
| `$B807-$B80B` | Номер и ревизия RFI |
| `$B811` | Флаги конфигурации: бит 7 кондиционер, бит 6 EGR, бит 5 автоматическая коробка, бит 2 отключение сигнализации, бит 1 ранний переходный режим по TPS |
| `$B812` | Флаги конфигурации 2 (бит 4 переходное топливо, бит 6 O2) |
| `$B813-$B816` | Настройка шины CCD |
| `$B817-$B819` | Маски ошибок, зажигающих лампу Check Engine |

См. также [карту ввода-вывода](io_map.md), [распиновку разъёма](pcm_connector.md) и

## Таймеры и прерывания

Таймер тактуется от E-clock / 4. С обычным кварцем 8 МГц (E-clock 2 МГц) один тик TCNT равен
**2 мкс**, счётчик переполняется каждые 131 мс.

| Вектор | Обработчик | Назначение |
|---|---|---|
| RESET | `ResetInterrupt` | Запуск |
| PAI (фронт PA7) | `Isr_PAI_CamPhase` | Фронты датчика распредвала (обе полярности): определение цилиндра по уровню сигнала коленвала *(выведено)* |
| PAOV | `Isr_PAOV` | Счёт переполнений аккумулятора импульсов |
| TIC1 (PA2) | `Isr_TIC1_CrankEvent` | Фронты датчика коленвала: главное событие двигателя; вызывает обработчики фронтов, которые планируют впрыск и искру *(выведено; у Ллойда — датчик распредвала)* |
| TIC2 | `Interrupt_SpeedometerSignal` | Датчик скорости автомобиля |
| TIC3 (PA0) | `Isr_TIC3` | Второй фронт сигнала коленвала (ширина прорези); запуск измерения длинного периода вместе с TOF *(выведено)* |
| TOF | `Isr_TOF` | Счёт переполнений таймера для длинных периодов |
| TOC1 | `Isr_TOC1_Periodic` | Периодическое прерывание каждые $03B9 тиков (около 1,9 мс) |
| TOC3 (PA5) | `Interrupt_DwellTimerA` | Драйвер катушки A: начало накопления и искра |
| TOC4 (PA4) | `Isr_TOC4_KnockSample` | Конец окна детонации: замер датчика детонации через АЦП |
| TOC5 (PA3) | `Interrupt_DwellTimerB` | Драйвер катушки B: начало накопления и искра |
| TOC2, IRQ, XIRQ, SWI, недопустимая команда, COP, монитор тактовой частоты, SCI, SPI, RTI | `Trap_*` | Не используются: обработчики записывают причину и перезапускают блок |

При сбросе записываются TCTL2 = $1A (IC1 по передним фронтам, IC2 и IC3 по задним) и TCTL1 = $2A
(OC3, OC4 и OC5 сбрасывают свои выводы при совпадении; OC2 от вывода отключён).

Имена регистров в исходном дизассемблере (унаследованные от турбированного SMEC) называют OC3 и OC4
драйверами форсунок, а OC2 «wastegate». На FCC катушки управляются напрямую через OC3/OC5, а четыре
форсунки отсчитывает внешнее устройство ввода-вывода (см. [engine_control.md](engine_control.md#положение-двигателя-и-расписание-событий)).

## Запуск и восстановление после сбоя

`ResetInterrupt` программирует системные регистры HC11 в первые 64 такта, как этого требует HC11
для защищённых регистров. Затем проверяется, сохранилось ли ОЗУ:

- `CountRamValuesFrom05to38` суммирует ОЗУ с адаптивной памятью, кодами ошибок и выученными
  значениями ($0005-$0036 и $0100-$014D);
- если сумма совпадает с сохранённой копией и есть сигнатура `$AAA5`, ОЗУ сохраняется (тёплый старт);
- иначе ОЗУ очищается и загружаются значения по умолчанию (холодный старт).

Каждый неиспользуемый вектор прерывания ведёт на маленькую заглушку `Trap_*`. Она ставит бит
причины в `BYTE00` и выполняет ту же инициализацию, что и сброс, но **без** очистки ОЗУ. Поэтому
после сбоя, срабатывания сторожевого таймера или недопустимой команды мотор сохраняет выученные
значения и коды ошибок.

| Бит причины | Ловушка |
|---|---|
| $01 | SCI / SPI / прерывание реального времени |
| $02 | XIRQ |
| $04 | Сторожевой таймер COP |
| $08 | Монитор тактовой частоты |
| $10 | Недопустимая команда |
| $20 | SWI |
| $40 | Сравнение выхода 2 |
| $80 | Вывод IRQ |

## Главный цикл и планировщик

`MainProgramLoop` выполняется раз в **$1500 тиков = 10,75 мс**. Это та самая единица «x 11 мс»,
которая встречается во многих калибровочных константах.

1. `MainSubLoop` выполняется на каждом проходе: сброс сторожевого таймера COP, «пульс» на $0409,
   измерение периодов, оцифровка напряжения бортсети, TPS и кнопок круиза, логика дросселя и
   барометра, пусковое топливо и другие задачи, выполняемые всегда.
2. Затем выполняется не больше **одного** из восьми подциклов `SubLoopA`..`SubLoopH`. Их биты
   запроса лежат в ОЗУ по адресу $0150; обслуживается младший взведённый бит, после чего он
   сбрасывается. Так распределяются медленные задачи (датчики температуры, диагностика ...).
3. Цикл измеряет, сколько занял проход (ОЗУ $0455, худший случай в $0454), и ждёт, пока TCNT дойдёт
   до следующего слота 10,75 мс.

Работа, критичная по времени (расписание впрыска и зажигания относительно положения коленвала,
замер детонации, накопление в катушках), выполняется в обработчиках прерываний, а не в главном цикле.

## Форматы таблиц

Почти все калибровки используют два формата.

### 2D-кривые «точка-наклон» (`Lookup4ByteTable`, $FA9D)

```
количество n
x0, y0, наклон0_ст, наклон0_мл
x1, y1, наклон1_ст, наклон1_мл
...
x(n-1), y(n-1)            ; у последней точки наклона нет
```

Для входа x меньше x0 результат равен y0. Иначе подпрограмма находит отрезок x_i <= x < x_(i+1) и
возвращает `y_i + (x - x_i) * наклон_i / 256`. Наклон хранится, а не вычисляется, поэтому если
изменить значение y, не пересчитав наклон, кривая получится неправильной. MP Tune пересчитывает
наклоны автоматически.

### 3D-карты (`Lookup3DTableRoutine_2`, $B437)

```
строки, столбцы, знак     ; знак: $00 беззнаковая, $80/$FF знаковая
строки x столбцы байт, построчно
```

Оба входа — координаты 0-255, которые получаются из передаточных кривых: например, `RPMSCL`
превращает обороты в координату столбца, а `MAPHI` превращает давление MAP в координату строки.
Координата равномерно распределяется по (столбцы-1) и (строки-1) интервалам, четыре соседние ячейки
интерполируются билинейно. Значит, точки по оборотам и MAP у карты задаются её передаточной кривой, а
не самой картой. Изменение `RPMSCL` сдвигает все карты, которые её используют.

## Контрольная сумма ПЗУ

`CaculateChecksum` ($56E7) складывает все байты $1200-$B5FF и $B800-$FFFF (8-битная сумма, окно
EEPROM пропускается). Результат должен совпасть с байтом по адресу **$B805** — последним байтом номера
детали. При несовпадении подпрограмма сообщает код ошибки 53 (внутренняя неисправность контроллера). В обоих
образах этого репозитория дескриптор этой ошибки выключен (бит 7 флагов сброшен, см.
[fault_codes.md](fault_codes.md)), так что ничего не записывается и мотор работает как обычно. В заводских
образах B559 (4874154/155/156/158/159) тот же дескриптор (там по адресу $D4F9) включён, так что
неверная сумма записывает код 53.

Тот, кто меняет калибровку, должен подогнать сумму свободным байтом. В заводских образах для этого
оставлен байт $FF50 со значением $FF. Часть образов, отредактированных в MP Tune и изученных в этом
проекте, эту проверку не проходит, так что проверяйте сумму после любого редактора.
